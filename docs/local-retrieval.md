# Local retrieval milestone

## Requirements and demo

Python 3.10+ and Git on PATH. No pip packages, credentials, model downloads, or network access are needed. Run commands from the public repository root. Use `python` or your Python executable; `-B` also suppresses bytecode generated by test imports.

```powershell
python -B src/research_search.py --mode demo search --question "refurbishment replacement parts"
python -B src/research_search.py --mode demo search --question "翻修 工时 零件"
python -B src/research_search.py --mode demo evaluate
python -B -m unittest discover -s tests -v
```

Demo mode reads only the bundled `data/demo/` fixtures. It does not read TECH_RESEARCH_DATA_DIR or legacy SPACE_DATA_DIR, dotenv files, credentials, or private configuration. All fixture statements and source identifiers are synthetic, not aerospace evidence. Demo JSON is emitted as UTF-8 with original Chinese characters.

## Implemented scope

Retrieval uses length-normalized BM25-style keyword scoring, query-term coverage, adjacent keyword phrase bonuses and numeric-match preference. Common English question words are ignored; Chinese multi-character runs use adjacent character pairs for ranking. Double-quoted phrases must occur in returned text. Single-word overlaps are suppressed for queries with three or more meaningful terms. Original text and citation locations are unchanged. These heuristics improve lexical specificity but do not establish answerability.

Indexes exist only in memory and are rebuilt on each command. There are no persisted embeddings, caches, telemetry, network calls, generated answers, automatic translation, semantic embeddings, or evidence-status predictions. Queries generally need the source language or shared vocabulary. This is not a general cross-language semantic search system.

## Required private boundary

Use sibling directories under a parent that is itself outside every Git working tree:

```text
workspace/
  technical-research-engine/      # public Git repository
  space-watch-private/            # external private directory, no Git
    documents.json
    questions.json
    question.txt
    sources/
    result-<random-id>.json
```

Never put private documents in the repository, even in an ignored folder. Never link the public repository to private material. Existing style guides and production templates can remain at their original external locations; they are not retrieval inputs by default. No private material needs to be uploaded to a cloud workspace.

For a fresh local setup, first resolve the parent path and verify it has no enclosing `.git` file/directory or Git working tree. Create the sibling private directory, then explicitly configure it in the current PowerShell session:

```powershell
# Run from the public repository root; the parent must not be another Git tree.
New-Item -ItemType Directory -Path ../space-watch-private
$env:TECH_RESEARCH_DATA_DIR = (Resolve-Path ../space-watch-private).Path
```

Skip directory creation if it already exists. The application requires an existing directory, resolves links, inspects ancestor Git markers, and probes Git with discovery-related environment overrides removed. It rejects Git working trees (including linked worktree markers), bare repositories, unavailable Git checks, and paths resolved into a Git tree. Manifest file references must stay within the data directory; linked files/directories, hard-linked inputs, and nested Git inputs are rejected.

Private commands save results exclusively as newly created `result-*.json` files directly in the selected data directory (`TECH_RESEARCH_DATA_DIR`, or legacy `SPACE_DATA_DIR`). Terminal output contains only a fixed success or error message. Open those JSON files locally to view passages and metadata. No production output directory is configurable inside the public repository, and no output fallback is used.

This protects normal use and accidental path mistakes; it is not a sandbox against another process maliciously replacing directories during execution. Filesystem permissions and local backups remain the user's responsibility. Do not redirect private results into Git or share them as public test artifacts.

## First aerospace application: curate private documents

1. Review existing private collections before adding material. For a new pilot, select ten public primary-source documents relevant to reusable-launch research, covering Chinese and English. Record rights and access restrictions privately; public availability does not authorize redistribution.
2. Manually save permitted UTF-8 text extracts under the external `sources/` directory. This version does not parse PDF, DOCX, HTML, or fetch URLs. Review extracted paragraphs against originals.
3. Create `documents.json` in TECH_RESEARCH_DATA_DIR as a JSON array. Each item requires `id`, `title`, `publisher`, `source_url`, `publication_date`, `language`, and `file`. Use a language tag such as `en`, `zh`, or `zh-Hans` (only English/Chinese retrieval is tested); use an ISO `YYYY-MM-DD` date or `unknown`. Never invent missing dates. Source URLs are metadata only and are not fetched. Optional `domain` is a nonempty string, preserved without inference; omit it when unknown. See the [domain model](domain-model.md) for exact validation and planned fields.

Schema illustration using explicitly synthetic values (replace with verified metadata privately):

```json
[
  {
    "id": "synthetic-example",
    "title": "Synthetic schema example",
    "publisher": "Synthetic fixture author",
    "source_url": "synthetic:schema-example",
    "publication_date": "unknown",
    "language": "en",
    "file": "sources/example.txt"
  }
]
```

IDs must be unique ASCII letters, numbers, underscores, or hyphens. Paths are relative to TECH_RESEARCH_DATA_DIR. Paragraph numbering starts at one and changes if you edit paragraph boundaries. Keep a private corpus version when annotating questions. This version's paragraph citations locate extracted text, not original PDF pages; verify those manually.

For sensitive questions, write the query into the external `question.txt` using a local editor, rather than putting it in shell history:

```powershell
python -B src/research_search.py --mode private search --question-file question.txt
python -B src/research_search.py --mode private evaluate
```

## Ten manually verified questions

Create external `questions.json` with ten unique question records: eight with verified evidence and two the collection cannot answer. Include both languages, terminology variants, and plans versus completed events. Review the entire small corpus when labeling an unanswerable question. Do not use score thresholds as labels.

Each record has `id`, `question`, `answerable` (boolean), and `expected_passage_ids` (array). Answerable cases require existing passage IDs; unanswerable cases require an empty array.

```json
[
  {
    "id": "synthetic-answerable",
    "question": "Which passage contains the synthetic example?",
    "answerable": true,
    "expected_passage_ids": ["synthetic-example:p1"]
  },
  {
    "id": "synthetic-unsupported",
    "question": "What information is absent from this synthetic collection?",
    "answerable": false,
    "expected_passage_ids": []
  }
]
```

Evaluation measures hit@5: the proportion of labeled answerable questions for which **at least one** expected passage is returned in the first five results. It does not measure complete evidence coverage. Unanswerable cases are excluded from that denominator and retain retrieved IDs for manual inspection; no answerability classifier or abstention score is implemented.

The bundled eight-question fixture set is a reproducible smoke test, not a held-out benchmark. Run the evaluation to obtain actual results; do not generalize its score to real research. Real document text, labels, outputs, and measured private results must remain external.

## Compatibility and migration

The generic entry point is `src/research_search.py`. Existing `src/space_search.py` CLI commands still delegate to the same implementation. Required manifest fields and paragraph IDs remain unchanged; optional `domain` is returned only when supplied.

`TECH_RESEARCH_DATA_DIR` takes precedence. If it is absent, `SPACE_DATA_DIR` remains supported. If it is explicitly empty, invalid, or points inside Git, the command fails instead of using the old setting. If neither variable is present, private mode reports a clear error. No process/user/machine environment setting is changed automatically.

To migrate an existing session without moving data:

```powershell
# Only when SPACE_DATA_DIR already points to your verified external directory:
$env:TECH_RESEARCH_DATA_DIR = $env:SPACE_DATA_DIR
```

Directory names are not prescribed. The aerospace sibling name above may remain unchanged. Existing files are neither moved nor copied, and private output stays in the selected directory. The repository checkout may retain its old folder name; that does not change the project identity or data selection.
